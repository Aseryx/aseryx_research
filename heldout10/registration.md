# Held-out set 10: pre-registration

> Public copy of the registration of held-out set 10. This is the text accepted on 2026-11-24, with one passage withheld and marked "[Withheld: ...]". Nothing else is changed. File paths in the text point into our private working repository.

**Accepted by Austin on 2026-11-24, before any file of set 10 was downloaded. The text below is fixed. It is published in `aseryx_research/heldout10/registration.md` and stamped with OpenTimestamps before any download.**

Set 10 compares two frozen versions of the quality score, v11.0 and v12.0, on files neither has seen. v12.0 is the version in the product since 2026-11-24; v11.0 is the version of the published record. Sets 7 to 9 were used to develop v12, so they cannot support a claim about it; set 10 is the test that can. Everything below is fixed before download and does not change after it. Results go to `formula/results/heldout10-<version>.json` and a report under `../reports/runs/`.

No version is expected to win. This registration states no prediction.

## Protocol

- **Versions and engines:** [Withheld: the registration names the exact engine build that runs each of the two versions (v11.0 and v12.0). Each version runs once on its named build, and every tool's SHA-256 is recorded in the report before scoring.]
- **One pass per version:** each version scores the set once. A run is repeated only when it ends without a result for a technical reason (out of memory, killed), with more memory and the same inputs, and the repeat is recorded. Nothing is rerun after looking at a score.
- **Scores compared:** v12.0's score against v11.0's headline score, as the published record reports v11.0. v11.0's data-alone score is reported beside it on every mark. No file declares anything: both versions read every file as published.
- **Sources:** each file comes from its publisher or the publisher's own portal, never a mirror. Only set 9's format fixes are allowed (decompression, encoding to UTF-8 where named, a delimiter changed, a records array extracted from a JSON envelope, a named slice). Each fix and each download's SHA-256 go in `../datasets/SOURCES.md`.
- **Frozen copies:** every file is downloaded once, hashed as downloaded and as converted, with the exact URL and the retrieval time (UTC). Both versions score the frozen copies only.
- **After publication:** the downloaded files and every scratch, twin and build folder are deleted to save disk space (Austin, 2026-11-24). The record keeps each file's source URL, retrieval time and SHA-256, the score runs, the proofs and the reports, so any file can be fetched again and checked against its hash.
- **Isolation:** no file of set 10 is used in development, the corpus or any other run until both versions have scored it and the results are published.

## How the files were chosen

1. **Candidates** were found by reading publishers' pages and portal metadata only, with no file or row requested: Socrata and CKAN open-data portals, agency bulk releases, generated relational data, and searches for publishers' own wording on validation and defects. Every candidate, its evidence and its status are listed in `heldout10-candidates.json`. One request was sent to a Socrata rows endpoint by mistake during the research (recorded in the candidates' Method section: HTTP 404, nothing received).
2. **Excluded before the draw:** any dataset or family used in sets 1 to 9 (`../datasets/SOURCES.md`, `HELDOUT8.md`, `HELDOUT9.md`), any host that refused scripted downloads in set 9, and candidates whose page showed no direct file.
3. **The draw:** `formula/tabular/harness/heldout10_draw.py`, seed 10, no network. Per label, the sorted ids of all candidates, whatever their status, are shuffled with the seed, so a later status change moves no one in the order. A first pass takes database-style candidates until 20 are taken; a second pass takes the rest in the same order until 60; the replacements continue the second pass. At every take: at most 3 files per dataset family (files of a family used in an earlier set count), at most 10 per cap group (the portal host, or the publisher on aggregator portals: open.canada.ca, data.gov.uk, data.gov.ie, data.virginia.gov, data.humdata.org), and for dirty files at most 20 per documented defect type. Candidates marked not eligible are skipped. The output, `heldout10-draw.json`, lists the drawn files in order and then the replacements in order (25 good; 18 dirty, where the caps left no more).
4. **Check of the drawn files, before registration:** for each drawn file and each replacement that entered, the licence and the direct file were read from its page, and the evidence quote was read against the labelling rules. A file that failed was replaced, in order, by the next replacement that had not failed, kept every cap and, while fewer than 20 database-style files were held, was database-style (`heldout10_final.py`, output `heldout10-final.json`). Every failure and its reason is in table D. Terms that grant no reuse licence (such as the City of Chicago's Data Terms of Use) fail the licence bar; field-level verification wording, generic accuracy disclaimers and statements that issues were corrected do not meet the labelling rules.
5. **No change after registration:** a file that fails at download is excluded, not replaced.

## Download safety

As set 9: only plain data is downloaded and nothing downloaded is executed; HTTPS on the publisher's domain or its documented storage host, a redirect elsewhere stops the download; at most 2 GB downloaded and 500 MB converted, larger files excluded; content checked from its bytes (CSV, TSV, plain text tables, JSON, JSONL, optionally gzip or zip with the set 9 archive rules); downloads go to a scratch folder outside the repo and are read as text only.

## Exclusions at download

A file is excluded and reported, and the marks are computed on the rest at the same percentages, when: its page at download states a licence outside the bar; it has fewer than 100 data rows (no version scores fewer than 100 effective rows) or breaks a size cap above; it cannot be downloaded (an error, a block or a bot challenge; none is worked around); or it fails a download safety check. A twin is excluded with its original. Excluded files are not replaced after download.

## Licence bar

Public domain (including US federal works), CC0, CC BY (any version), ODbL, ODC PDDL, ODC-BY, the UK Open Government Licence and the Canadian and provincial open government licences, the Statistics Canada Open Licence, NYC and OPEN-NY open data terms, and Apache 2.0 for generated data's generator.

## Labelling rules

- **good:** the publisher documents validation, verification, audit, quality assurance or curation of this table, or the table is generated relational data; nothing in the documentation says otherwise.
- **dirty:** the publisher documents a defect in this table: suppressed or sentinel values, redaction, transcription or entry errors, self-reported or unaudited values, known missing periods or gaps, or duplicates. The defect type is recorded from the publisher's words.

Every label names its source: the publisher's own words and the page they appear on. No label was chosen by looking at the data.

## Composition

- **60 good** and **53 dirty** files. The dirty side is 53, not 60: after the checks no dirty replacement was left, and no candidate was added after the draw. The marks are shares, so the comparison is unchanged. Database-style (one row per entity or event, a key, typed columns): 31 good and 34 dirty.
- **Up to 20 twins:** the originals are database-style good files, one per publisher, in the order of table C; the first 20 with 1,000 to 500,000 rows at download are used, each with one of set 9's dirty recipes D1 to D10 (table C). The engines are set 9's. Expected dirty.
- **Symmetry part:** every database-style good file is also written as JSONL and loaded into a local PostgreSQL and read back through the Aseryx Runtime; each copy must score as the CSV does under v12.0. The local database is removed after scoring.
- No check cases: set 9's ten check cases test findings that v12.0 does not report (declarations, lists, codes, slots).

## Marks

Each mark for each version with a 95% percentile bootstrap interval (`formula/tabular/harness/bootstrap.js`, 10,000 resamples, seed 10, resampling by dataset; a twin goes with its original), and v12.0 minus v11.0 on the same resamples:

1. Good files ranked above dirty files, a tie counted as half (the primary mark).
2. Dirty files below 70 (the share; 80% is reported beside it, not a condition).
3. Good files at 90 or more.
4. Good files below 50.
5. Twins: the original scores at least its twin.
6. The same marks on the database-style files alone.
7. Symmetry: every copy scores as its CSV (v12.0 only).

A file a version cannot read meets no mark for that version. Reported beside the marks, not marked: results by defect type, portal and format; time and peak memory of each version on the five largest files.

## Claim rule

The public statement about v12.0 against v11.0 is chosen by these rules:
1. **"v12 separates good data from dirty better than v11":** mark 1 is higher for v12.0 with the paired interval excluding zero, and no other mark is worse for v12.0 with its interval excluding zero.
2. **"v12 matches v11's accuracy from the data alone, with a simpler, faster proof":** rule 1 does not hold, and no mark is worse for v12.0 with its interval excluding zero.
3. **Otherwise** the result is published as it is, naming the marks where v12.0 is worse.

The database-style files are reported under the same rules on their own. Every mark and every comparison is published, none is picked.
