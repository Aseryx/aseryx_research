# Held-out set 9: pre-registration

> Public copy of the registration of held-out set 9. This is the text accepted on 2026-11-09, with two passages withheld and marked "[Withheld: ...]". Nothing else is changed. File paths in the text point into our private working repository. The registration calls the versions v10.2 and v11.0; the results call them v10 and v11.

**Accepted by Austin on 2026-11-09, before any file of set 9 was downloaded. The text below is fixed.**

Set 9 is the first held-out set scored on every frozen formula version at once: v6, v7, v8, v9, v10.2 and v11.0, each once, on the same files. It exists to compare the versions on data none of them was tuned on, with intervals tight enough to tell them apart where they differ. Everything below was fixed on 2026-11-09, before any file was downloaded, and the same text is on the Notion page "Appraisal Benchmark Datasets: Known Good vs Bad". Nothing here changes after download. Results go to `formula/results/heldout9-<version>.json` and a report under `../reports/runs/`.

No version is expected to win. This registration states no prediction for any version.

## Protocol

- **Versions and engines:** [Withheld: the registration names the exact engine build that runs each of the six versions (v6, v7, v8, v9, v10.2 and v11.0). Each version runs once on its named build, and every tool's SHA-256 is recorded in the report before scoring.]
- **One pass per version:** each version scores the set once. A run is repeated only when it ends without a result for a technical reason (the process runs out of memory or is killed), with more memory and the same inputs, and the repeat is recorded. Nothing is rerun after looking at a score.
- **Primary score:** the headline score. For v11.0 the data-alone score is reported beside it on every mark. v6 to v8 report one score.
- **Declarations:** none. No file declares a label column, a separator or any other declaration (`formula/corpus/labels/heldout9-labels.json` is empty), so all six versions read every file as published. v11.0 detects a label column itself; v6 to v9 check label conflicts only on a declared label, so on set 9 they check none.
- **Sources:** each file comes from its publisher or the publisher's own portal, never a mirror. Only the format fixes set 8 allows: decompression, character encoding to UTF-8 where named, a header row added from the publisher's documentation, a delimiter changed, a records array extracted from a JSON envelope, XML written as records, a named slice. JSON and JSONL written from tables follow `formula:formats`. Each fix and each download's SHA-256 go in `../datasets/SOURCES.md`.
- **Frozen copies:** every file is downloaded once. The download and the converted file are hashed (SHA-256) and kept unchanged in local storage (`data/calibration/heldout9/`, not committed; dataset licences). Beside each hash go the exact URL or API query fetched and the retrieval time (UTC), so a frozen copy of a live table can be described even though nobody can fetch the same bytes again. Every version scores the frozen copies only. The copies are kept after scoring, so the set can be scored again.
- **Isolation:** no file of set 9 is used in `formula:dev`, the corpus, a candidate or any other run until all six versions have scored it. After that it is development data.

## Download safety

Only plain data is downloaded, and nothing downloaded is ever executed.

- Every link is HTTPS on the publisher's own domain or the storage host it documents, named per file below. A redirect to any other host stops the download.
- Each download has a size cap: 2 GB as downloaded, 500 MB as converted. Larger files are excluded, not sliced after the fact.
- A file is kept only if its content is the format named below (checked from its bytes, not its name): CSV, TSV, plain text tables, JSON, JSONL or XML, optionally in gzip or zip. An archive is opened only if every member is one of those formats or plain documentation text, no member path is absolute or leaves the folder, and it inflates to no more than 100 times its size. Anything else (a spreadsheet, a database, a binary, a script, an executable) excludes the file.
- Downloads go to a scratch folder outside the repo and are converted there by `formula/corpus/heldout9-tools/`, which reads them as text only.

## Exclusions, decided now

A file is excluded and reported, and the marks are computed on the rest at the same percentages, when:
- its source page at download states a licence outside the bar;
- its row count differs from an exact count the publisher documents (where the publisher documents no exact count, the rule does not apply and the count found is recorded at download);
- it cannot be downloaded (an error, a block, a bot challenge: none is worked around);
- it fails a download safety check above.
A twin is excluded with its original.

## Licence bar

Public domain (including US federal works), CC0, CC BY (any version), ODbL, ODC PDDL, the UK Open Government Licence, Licence Ouverte, DL-DE BY. Every file below was checked against it before registration; the results are meant to be published by dataset name.

## Labelling rules

As set 8:
- **good:** the publisher documents curation or validation, and nothing in the documentation says otherwise. Expected 90 or more.
- **usable:** the only documented defects are duplicates under 18%, or columns with 1 to 10% of their values missing. Expected 70 to 89.
- **dirty:** a documented defect beyond that: broken records over 1%; a column over 10% missing, where the blanks are documented as not collected or not given rather than not applicable; invalid or placeholder values in over 10% of a column; duplicates of 18% or more; labels that disagree on the same features. Expected below 70.
- **twins:** dirty when an injected rate crosses a dirty threshold above, usable otherwise. The clean original keeps its own label.

Every label below names its source: the publisher's documentation for good files, and for dirty and usable files the document that states the defect, with its URL. No label was chosen by looking at the data.

## Pass marks

The marks of set 8, at the same shares:
1. Good files score 90 or more: at least 80% of the good files.
2. Dirty files score below 70: at least 80% of the dirty files. Usable files are reported against 70 to 89, outside this mark.
3. A good file scores above a dirty file in at least 90% of the good and dirty pairs; a tie counts as half.
4. Twins: the clean original scores at least its twin in at least 90% of the pairs.
5. Check cases: all 10 findings match their written expectation. They are set 8's ten recipes generated again with seed 9: they re-test the automatic checks, they add no new evidence about real data, and only v11.0 reports these findings (the others score 0 on this mark by construction).

A file a version cannot read meets no mark for that version.

Reported beside the marks, not marked: results by field, language and format; the data-alone score beside v11.0's headline; twins by recipe.

Two secondary views of marks 2 and 3, each reported beside the full marks and never instead of them:
- **Dirty files with a stated rate:** only the dirty files marked `rate` in table B, whose evidence gives the share of cells or rows affected, or a count with its denominator, in the publisher's own documentation, or computable from counts the publisher publishes (its portal's counts). A rate from a third party (a paper, an audit) does not count for this view.
- **By kind of defect:** marks 2 and 3 for each kind named in table B: `suppression` (cells withheld for statistical secrecy, documented as not given), `missing` (blanks or placeholder codes documented as not collected or not given), `errors` (values documented as wrong, misspelt or unverified) and `duplicates`. Suppression is labelled dirty because a buyer cannot use withheld cells, and the labelling rule's "not given" covers it; this view shows whether those files drive the dirty mark.

## Comparing versions

- **Intervals:** every mark of every version with a 95% percentile bootstrap interval, `formula/harness/bootstrap.js`: 10,000 resamples, seed 9, resampling by dataset (a twin goes with its original).
- **Paired differences:** for every two versions, the difference of each mark on the same resamples, with its 95% interval and the share of resamples in which the later version is ahead. A difference is described only as "the interval includes zero" or "the interval excludes zero"; every pair and every mark is reported, none is picked.
- **Reader-fair view:** v6 to v9 read comma-separated UTF-8 CSV, JSON and JSONL only. For them, each file in another format (TSV, another separator, a header cell with no name) is also written as plain CSV with `formula/replication/plain_csv.py` (values unchanged; only the separator, and a nameless header cell named `column_<position>`) and scored once. This view is reported beside the as-is result, never in place of it. A file that only becomes readable by removing the defect it tests (a broken-record twin) is not converted.
